# Admit a signed release to the frozen HTTP reference replay

The original eight-argument `scripts/verify-native-http-reference.sh` invocation
retains its historical image and C9 native executable pins. Use the explicit
`--current-admission ADMISSION_JSON` option for a later signed release. This
changes admission only: the same frozen 14 cases run at both CPU caps, in four
native processes, against the same raw upstream UTF-8 bodies. Whitespace and
TIFF page separators are compared without normalization. This gate makes no
850-tensor, lifecycle, quality-corpus or performance claim.

The current controller can have a different producing commit from the signed
release and telemetry driver. It records both identities. It accepts the
telemetry identity before `native_equivalence_passed` becomes true; successful
admission is not evidence that the pending HTTP requests passed.

## Retain the admission inputs

Authenticate the candidate index and all six image signatures, SPDX and release
evidence attestations using the release's exact workflow identity, source SHA,
ref and OIDC issuer. Retain the actual verifier outputs, command/exit receipts,
bundles and raw OCI provenance. The offline helper does not run Cosign or replace
this external verification. Its result binds these already verified receipts to
the native executable, materials, approved assembly and model inventory; an
invented `passed` boolean is insufficient.

Place the following witnesses beneath one admission directory. The packet's
`files` object has exactly these keys. Each value is
`{"path":"relative/path","sha256":"64 lowercase hex characters"}`; compute the
hash from the actual file. Absolute paths, symlinks and parent traversal fail.
Keep the complete raw resolution directories and complete native material tree,
not only the manifest files named in the packet.

| Key | Existing release/local witness |
| --- | --- |
| `candidates` | `signing/candidates.json` |
| `index_bundle` | `signing/candidates.sigstore.json` |
| `signing_result` | `signing/result.json` |
| `index_steps` | `signing/index/steps.tsv`, with successful `verify-blob` |
| `native_steps` | `signing/native/steps.tsv`, with successful image/SPDX/evidence verification |
| `native_signature` | Successful native `verify.attempt-N.stdout` |
| `native_sbom` | Successful native `verify-sbom.attempt-N.stdout`, containing the actual SPDX DSSE payload |
| `native_evidence` | Successful native `verify-evidence.attempt-N.stdout` |
| `release_manifest` | `evidence-files.sha256`, whose exact hash/size is in the verified attestation |
| `native_provenance` | `images/native-provenance/result.json` |
| `native_resolution` | `images/native-resolution/result.json` and its raw descriptor/config siblings |
| `native_container` | `images/native-material-container.json` |
| `materials` | `materials/native/SHA256SUMS` and every listed file |
| `build_identity` | `materials/native/build-identity.txt` |
| `native_binary` | `bin/indra-server` |
| `assembly` | Approved four-parent receipt described below |
| `assembled_resolution` | Local COPY-only assembly's raw resolution `result.json` and siblings |
| `assembled_container` | Actual container inspection bound to that assembly |

The packet has `schema_version:1`, `source_sha` (the signed release's full SHA),
`assembled_image_root` (`sha256:…`), `native_sha256`,
`models_inventory_sha256`, and the `files` object. The model hash is SHA-256 of
the sorted relative-path inventory generated by the controller:

```sh
(cd "$models" && LC_ALL=C find . -type f -print0 |
  LC_ALL=C sort -z | xargs -0 -r sha256sum) > models.sha256
sha256sum models.sha256
```

The assembly receipt has `schema_version:1`, the same `source_sha`,
`assembled_image_root`, `native_sha256`, `native_materials_sha256`, and exactly
four `parents`: `native`, `gateway`, `bridge`, `tika`. Each parent contains its
exact signed candidate `reference` and `root_digest`. The local image preserves
the signed Tika Java runtime and copies only the admitted signed runtime roles;
keep its Dockerfile/build metadata and parent/raw daemon proofs with the receipt.
This receipt is reviewed assembly provenance, not a signature on the local image.

The helper checks actual witness hashes, index/source coordinates, verified
signature and attestation subjects, basic SPDX document fields, signed release
manifest membership, complete
native material checksums and the build identity's native hash. It reuses
`verify-daemon-image.sh bind` to validate both retained raw OCI graphs and actual
container inspections. The native configuration's source label must match the
release. The replay subsequently resolves the actual executed image again and
checks the actual client and native executable bytes in every process.

## Execute correctness only

Run from a clean committed controller checkout. The static client's producing
receipt and complete tracked source path/byte closure must match that checkout.
The exact signed-release telemetry identity is reused without restamping its
source SHA to the controller's SHA.

```sh
scripts/verify-native-http-reference.sh --current-admission "$admission" \
  "$static_client" "$identity" "$assembled_image_root" "$models" \
  "$inputs" "$raw_reference" "$client_build_receipt" "$new_output"
```

Keep the admission directory and new output together. A successful run retains
28 individual raw bodies, wires, comparisons, four process/resource proofs and
cleanup receipts. Correctness uses CPU 12 and 12,13, at 1/2 CPUs, 3 GiB and zero
swap, with the unchanged 8 MiB worker stack. Timing requires the separate
producer-matched telemetry wrapper for the admitted source and reviewed timing clearance; this command supplies
neither. Preserve failed attempts and their partial outputs.

Offline controls require no images, model loading, signatures or inference:

```sh
bash tests/current-http-reference.sh /absolute/new-admission-controls
bash tests/daemon-image-identity.sh /absolute/new-daemon-controls
```
