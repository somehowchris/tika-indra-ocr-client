# Kubernetes node cgroup ownership

[Focused run 39225961004](https://github.com/somehowchris/tika-indra-ocr-client/actions/runs/39225961004/job/117972194499), controller `b4ee65a`, replayed the original source-`5ae8b82` images and harness. Original artifact/source admission, the corrected CRI parser, static harness checks and both image bindings passed. The gate then failed before namespace creation: Docker declared one CPU, while the cgroup selected from its host PID reported `max 100000`. Its effective CPU set was `0`. No application pod, OCR or lifecycle result follows.

The failed run did not retain the raw `/proc/4342/cgroup` path or its Docker-owned ancestor quota. A nested systemd process scope is therefore a source-backed explanation to test, not an observed ancestor quota. The pinned [kind entrypoint](https://github.com/kubernetes-sigs/kind/blob/407a9675e6d9af1200b5f57f9ca52ec6cdacce74/images/base/files/usr/local/bin/entrypoint#L268-L269) moves root processes into `init.scope`; a child may inherit a numeric Docker limit while its own local quota is `max`.

The corrected gate requires Docker's systemd cgroup-v2 driver and resolves the unique `docker-<full container ID>.scope` ancestor from the captured host PID record. It rejects substring identities, another Docker owner, repeated owners, traversal, symlinks, excessive depth and malformed whole-record bytes. The live container ID/PID and unchanged PID path are checked around observation. Both process and owned-scope counters and the full ancestor chain are retained.

For each CPU limit, the exact Docker-owned scope must have a numeric quota equal to one or two CPUs and the exact effective CPU affinity. An unlimited owned quota still fails. Ancestor limits are retained observations; they do not establish isolated benchmark hardware or ancestor-budget equivalence. Existing pod CPU shares, 1/2-GiB container memory limits, zero swap, image identity, accepted-work drain, terminal status, OOM and cleanup gates remain required.

Offline fixtures reproduce the nested-leaf distinction and reject wrong owners/quotas, NUL/CR/tab bytes and unterminated trailing records. Exact trailing-byte probes preserve the earlier helper's incorrect acceptance and the corrected rejection. Synthetic fixtures establish parser behavior, not a real host cgroup or Kubernetes runtime pass. A new focused replay must retain the actual path/owner evidence and complete both CPU lifecycle gates; final current-source reference, trace, signing and SDK acceptance remain separate.
